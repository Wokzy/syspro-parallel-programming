## Определения

- CSjA: thread A executes critical section for j-th time.
- Mutual exclusion: Critical sections of different threads do not overlap. ∀A, B, k, j CSkA → CSjB or CSjB → CSkA
- If some thread attempts to acquire the lock, then some thread will succeed in acquiring the lock. If thread A calls lock() but never acquires the lock, then other threads must be completing an infinite number of critical sections.
- Freedom from starvation (lockout freedom): Every thread that attempts to acquire the lock eventually succeeds. Every call to lock() eventually returns.

- Доказывать будем в предположении, что интервалы событий записи и чтения не пересекаются.

### Доказательство mutual exclusion:
1. Пусть есть `n` потоков и `n` уровеней `0..n-1`. Будем говорить, что поток A прошёл уровень `L: [1...n-1]` если он завершил свой цикл ожидания. Прохождение уровня `n-1` эквивалентно исполнению потоком критической секции. Уровень `0` обозначает не-критическую сецкию. Все потоки всегда "прошли" уровень `0`.
2. Докажем индукцией по номеру уровня `L`, что потоков, прошедших уровень `L` не больше, чем `n - L`:
  1. База индукции: `L=0` очевидно
  2. Предположение: уровень `L - 1` прошло не больше, чем `n - L + 1`, а потому и уровень `L` не могло пройти больше, чем `n - L + 1`
  3. Индукционный переход: Предположим, что уровень `L` прошло `n - L + 1` потоков.
    - Пускай `A` - последний поток из `L + 1`, который записывает себя как жертву на уровне `L`. То есть для любого потока `B != A` верно, что `(victim[L] = B) -> (victim[L] = A)`.
    - При этом из кода следует: `(level[B] = L) -> (victim[L] = B) -> (victim[L] = A) -> (inspect level[K] >= level[A] for K != A)`. Поскольку `level[B] >= level[A]`, то `A` не завершит свой цикл ожидания, а потому не пройдёт уровень `L`, как следствие, потоков, прошедших уровень `L`, не больше, чем `n - L`
Уровень `n - 1` прошло не больше `n - n + 1 = 1` потоков.

### Доказательство starvation freedom
1. Докажем обратной индукцией по номеру уровня `L`, что любой поток, прошедший уровень `L` сможет исполнить критическую секцию.
  1. База: для `L = n - 1` по определению.
  2. Предположение: Если поток прошёл `L + 1` уровень, то он сможет исполнить критическую секцию.
  3. Переход от обратного: Пусть поток `A` прошёл уровень `L` и "застрял" в цикле ожидания для прохождения уровня `L + 1`, по предположению индукции рано или поздно потоки, прошедшие уровень `L + 1`, исполнят критическую секцию, и сделают `unlock()`. Поскольку `A` записал `level[A] = L + 1`, то никакой из потоков != `A`, прошедший уровень `L` не сможет пройти уровень `L + 1`. Более того, потоки, которые к моменту `level[A] = L + 1` прошли уровень `L - 1`, но не прошли `L`, пройти `L` не смогут. Пускай все потоки, которые прошли уровень `L` теперь застряли в цикле ожидания `L + 1` и поля `level` и `victim` больше не меняются. Если такой поток `A` единственный, то он пройдёт уровень `L + 1` тк `(level[K] >= level[A]) == false`, если таких потоков больше, и, как было сказано ранее, поле `victim` больше не меняется, то все потоки (назовём их `A, B1, ..., Bk`) "застряли" на `victim[L + 1] == A == B1 == ... == Bk`, чего быть не может.
